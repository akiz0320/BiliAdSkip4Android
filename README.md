安卓端 **B站 口播广告自动跳过**：识别视频里「UP 主口播的广告段落」，命中后自动跳到广告结束处。
跟着 B站 播放自动启动，全程无需手动开关。

## 功能

- **进 B站 即自动开始监测**（还没播放也会启动），离开 B站 自动进入待命，离开满 3 分钟完全退出
- 广告判定：官方字幕优先 → 大模型分析；无字幕时可选降级为 Groq 音频转写
- 命中广告自动 `seekTo` 跳过，并**校验跳转结果**（未生效会重试，连续失败会明确提示）
- 悬浮球实时显示启停状态（圆球 / 侧边细条两种形态），可拖动吸边、轻点暂停、长按打开主界面
- 跳过前 5 秒给出预告气泡，跳过成功 / 失败均有提示
- 主界面：运行状态、权限引导、AI 配置、运行日志、关于与防伪

## 工作原理

```
B站 MediaSession ──► 从 MEDIA_ID 反推 aid ──► 解析 bvid/cid
        │                                        │
        │                              官方字幕优先（aisubtitle）
        │                              无字幕 → Groq 音频转写
        │                                        │
        │                              大模型判定口播广告区间
        │                              （云端缓存仅作加速层）
        ▼                                        ▼
轮询播放位置 ──────► 进入广告区间时 seekTo 跳过 ──► 校验跳转结果
```

- 读会话：通过「通知使用权」读 `MediaSessionManager.getActiveSessions()`；B站 会同时挂多个会话（有位置恒为 0 的代理会话），所以按"像不像真播放器"（有无视频 id / 位置是否推进 / 能否 seek）挑会话
- 判广告：把官方字幕文本交给大模型（任意 OpenAI 兼容接口）判定口播广告区间；云端缓存只作加速，不作为真值源
- 跳过：`MediaSession.TransportControls.seekTo()`，调完会再校验播放位置是否真的移出广告区间
- 在岗判定：用系统「使用情况访问」判断 B站 是否在前台，驱动在岗 / 待命 / 完全退出三态
- 保活：前台服务 + 悬浮球窗口（进程被系统视为可见，避免被冻结）

## 安装

1. 从 [Releases](https://github.com/akiz0320/BiliAdSkip4Android/releases) 下载 `BADS-v1.0.0.apk`（支持 Android 6.0+）
2. 安装后建议先[校验签名](#防伪校验)，再授予权限

## 权限说明

| 权限 | 为什么需要 |
|---|---|
| **通知使用权** | 第三方应用读 B站 `MediaSession`（也就是"B站 在放什么、放到哪了"）的**唯一合法途径**，没有它无法识别视频 |
| **使用情况访问** | 判定「B站 是否在前台」的唯一依据。没有它就只能靠"有没有播放会话"反推，用户只打开 B站 首页、还没点视频时会判不出来（球不出现、开关不启动） |
| **显示在其他应用上层** | 悬浮球窗口：既是状态指示灯，也是**保活**的关键——普通后台线程在别的 App 占前台时会被系统冻结 |
| **电池优化白名单** | 避免系统在息屏 / 低电时把后台服务掐掉 |

Android 13+ 会额外弹一次**通知权限**（POST_NOTIFICATIONS），授予即可，拒绝也不影响跳过功能。

## 首次配置

1. 打开应用 → 「手机权限申请」授予上面 4 项权限
2. 「AI 配置」填大模型（Base URL / API Key / Model，任意 OpenAI 兼容接口；不填则只能靠云端缓存命中）
3. 点一次「启用」，之后全自动

日常使用：悬浮球轻点 = 暂停 / 恢复，长按 = 打开主界面，拖动 = 换位置（8 秒不用会自动贴边变细条）。
手动暂停是**粘性**的：暂停后 B站 再播放也不会自动恢复，直到手动恢复。

本仓库是**唯一发布来源**，APK 只从 Releases 下载。发布者签名证书指纹（所有版本一致）：


```bash
# 校验下载到的 APK（推荐）
keytool -printcert -jarfile BADS-v1.0.0.apk   # 输出的 SHA256 应与上面一致

# 校验已安装的应用
#   应用内 → 拉到底 → 「关于与防伪」→ 看「本机签名指纹 SHA-256」，必须与上面一致
```

> 自己用 debug 密钥构建的包指纹必然不同，属正常现象。

## 数据与隐私

| 数据 | 去向 | 是否上传 |
|---|---|---|
| 视频 `bvid` | 云端缓存服务 `/api/cache/{bvid}` | 会上传（只有 bvid，不含字幕、音频、账号） |
| 官方字幕文本 | 你配置的大模型接口 | 会上传（用你自己的 Key，直连） |
| 音频（仅在无字幕且配了 Groq Key 时） | `api.groq.com` | 会上传（用你自己的 Key） |
| B站 登录 Cookie | 仅本机 `SharedPreferences`（明文） | 不上传，只用于取官方字幕 |

> Cookie 以明文保存在应用私有目录，未做加密；介意可以不登录（代价是没有官方字幕，只能用音频转写）。
> 云端缓存地址在代码里可替换为自己的服务。

## 已知限制

- 只在 B站 处于前台时工作；离开超过 3 分钟会完全退出。完全退出后，若只是打开 B站 首页浏览、还没点视频，不会自动拉起（等 B站 出现通知或播放会话才唤醒）
- 识别依赖官方字幕 + 大模型，**可能误判**（把正常内容当广告，或漏掉广告）；音频转写方案更慢也更易错
- 未登录 B站 时拿不到官方字幕，只能靠音频转写或云端缓存
- 悬浮球的保活依赖"显示在其他应用上层"权限；部分 ROM 的省电策略仍可能限制后台，请一并加入白名单
- 只在 MuMu 模拟器与少数真机上验证过

## 自行构建

环境：JDK 17、Android SDK（`compileSdk 35` / `buildTools 35.0.0`）、Gradle 8.12。

```bash
gradle -p BiliAdSkip assembleDebug
# 产物：BiliAdSkip/app/build/outputs/apk/debug/app-debug.apk（自动 debug 签名，可直接安装）
```

> Release 构建需要维护者本地的签名配置，属本机信息，不参与仓库；fork 后如需发自己的包，配置自己的 keystore 即可。
